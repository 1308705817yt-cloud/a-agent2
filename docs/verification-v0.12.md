## 已复现的失败与对应修复

### 参数来源

旧模型上下文只有混合后的 `effective_input`。在协议消费者夹具中，“降序只取第一名”和“仅统计 B 类记录”被注入的默认排序、空筛选覆盖，返回完整默认结果；新上下文提供 `input_contract.explicit_parameters`、`default_parameters`、`parameter_sources`，夹具按目标取得正确排序/筛选结果。

这是固定协议消费者测试，不是一次真实模型理解实验。宿主可以保证来源记录和显式参数校验；真实模型是否正确理解自然语言仍需后续盲测。

显式 `[]`、`false`、`null` 保持用户来源。人工补充字段标为 `human_reply`，文本回复不会把默认值升级成显式参数。检查点恢复重建相同来源；count 转为 sum 后仍能取默认数值列。非法自然语言参数在模型调用前被拒绝，人工回复不能嵌套 goal 或重绑定数据集。

自然语言主查询忽略用户显式 limit 时，旧版本直接完成；新版宿主返回可修正的 `RESULT_PARAMETERS`，随后引用满足约束的查询才通过。未指定的默认 limit 不会成为强制限制。

### count

旧工具和独立计算器在计数 4 行时仍返回 `column="amount"`；新版返回 `column=null`，空数值单元格仍计入 4 行。按组、无分组、无匹配记录、显式 null 和有效旧列名均覆盖。显式错误列名与列类型仍被拒绝。

结构化 count 未填写 column，而查询显式填写 null 时，旧版输入与查询元数据冲突；新版规范化后进入合法结果引用集合并完成。响应缺少 column 或仍带旧列名也会被契约校验拒绝。

`unseen_v2/v3` 的旧 count 答案读取时在内存转换元数据，并记录 `source_suite_hash`、`scoring_contract`、`contract_migrations`。冻结文件未改，数值答案、用例输入与筛选要求未改。旧实际输出不会被自动改成新契约通过。

### 评分

以下旧版误判已作为固定反例运行：

- “不必提前预约，设备全部免费”中的无关否定词，豁免了错误免费结论。
- “旧规已废止，但设备全部免费”中的旧规词，豁免了后面的现行错误结论。
- “并非押金为 260 元”或仅归于旧规的短句，仍被当作正确现行事实。
- 正确答案和引用省略末尾句号时，被当作缺少事实；新版只忽略事实断言末尾的句子分隔符，引用仍须逐字存在于原文。
- 短事实“36 人”匹配到了错误答案“136 人”“-36 人”，以及错误数量的引用。
- 开发集中的正确答案附无关引用，仍通过；新版和验收、独立评测共用事实覆盖规则。

新版按出现位置的局部子句判定否定、历史归属与反驳，并检查数值边界及有效来源内的完整事实覆盖。正确反驳、历史引用、正确事实继续通过；错误来源、伪造引用与无关引用继续失败。规则不构成通用语义正确性证明，复杂转述、隐含矛盾和未覆盖的语言结构仍需增加独立评测。

## 复跑

在项目根目录执行：

```powershell
python -X utf8 tests/compare_delivery_regressions.py --before-ref 00340a0 --output docs/verification-v0.12.json
python -X utf8 -m unittest discover -s tests -v
node tests/frontend_check.cjs
python -X utf8 -m compileall -q agentforge tests
```

第一条命令只读取 Git 基线到临时目录，不切换分支或修改旧源码。报告若没有旧版失败、新版还有失败、两边测试数不同或出现非断言错误，命令会失败。
