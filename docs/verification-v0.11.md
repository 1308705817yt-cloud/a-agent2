## 失败点与修复记录

- 快递重量的两个自然语言任务失败：Agent 将宿主注入的默认筛选、排序和条数限制视为用户显式参数，覆盖了“只取前两项”和“仅调整记录”的要求。运行时在合并参数后未提供用户参数来源，是有证据支持的可能原因，尚未修复。
- 厨房账本待处理记录数算对了（3），但返回的 `column` 为 `kg`，未归一为要求的 null，属于结果契约问题。
- 社区会议室首版在精确引用标点上失败；第二版给索引片段补回标点，却违反了冻结的工具计算样例。第三版恢复工具契约，并要求最终引用回到已读取原文逐字截取。其最终独立结果为 6/6。

社区会议室逐版本开发与验收记录：

- v1 development：18/19；失败用例：goal_dev_application_evidence
- v2 development：4/6；工具失败后未执行业务场景；失败用例：dev_evidence_multi_document_status、dev_evidence_empty_markers_truncated
- v3 development：19/19
- v3 acceptance：17/17

后续优先改进参数来源标识、count 结果归一、长设计调用的可观察性与阶段拆分，以及修复前检查工具契约和回答要求是否同时成立。不能只靠增大超时或删除负面测试取得通过。
