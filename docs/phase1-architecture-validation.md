## 修复的问题

1. 旧测试基线为 243 项，其中 1 项失败：CSV 输入提前校验后直接返回，绕过了旧输出钩子的错误保护。修复后错误响应仍经过输出钩子，并禁止生成代码隐藏原错误；旧断言未修改。
2. SQLite `COUNT(*)` 的无列读取可能不带数据库名，原授权器误拒绝合法计数。现在支持该回调，并阻止临时或附加数据库中的同名表借此读取。
3. CSV 列名包含 NUL 时泄漏原始 SQLite 异常。现在返回可诊断的错误；装载阶段其他 SQLite 错误也有明确归属。
4. 绑定记录未完整检查来源名、评测状态及嵌套结构。现在验证完整审计字段并重新规范化原始行，畸形记录一致拒绝；仅改变源列顺序仍可按字段名绑定。
5. 必需工具直接进入循环、计划拒绝及快速执行失败转入循环时，部分轨迹未记录路径切换。现在明确写入 `routing=adaptive_loop`。
6. 可信 SQL 的 `schema` 观察曾可被用作最终计算结果。现在从可完成的结果引用中排除结构、预览和档案，并在最终校验再次检查。

## 零自定义工具验收与导出

使用真实 `AdaptivePlanner` 和 `FactoryAgent`，由符合 schema 的夹具提供需求、设计和两类测试响应。内置能力满足需求时 `custom_tools=[]`，复用 `observed-v1`，不发送源码生成请求。实际执行冻结测试及保留验收，并确认两份报告绑定同一个产物指纹。

导出的 ZIP 在另一个临时目录解压运行，清空 `PYTHONPATH`，并将 Codex 路径指向不存在的程序。结构化指标仍成功且模型调用为 0；本地验证器将自定义工具检查明确标为 `not_applicable`。源文件篡改会被完整性校验拒绝。兼容数据绑定经过独立 CLI、持久化执行、人工接续及冻结运行时重载验证，新数据始终标记 `not_evaluated_on_new_data`，原验收证据不变。

宿主模块测试通过并不等于每个生成产物都已做过独立的指标或 SQL 业务验收。因此 manifest 中这两类能力的 `not_independently_evaluated` 标记继续保留。

## 复现

```powershell
python -X utf8 -B tests/run_phase1_validation.py
```

默认报告与完整日志分别写入 `.agentforge/validation/phase1-architecture-results.json`、`.agentforge/validation/phase1-full.log`。更新仓库证据时显式指定：

```powershell
python -X utf8 -B tests/run_phase1_validation.py --report docs/verification/phase1-architecture-results.json
```

也可直接运行同一完整测试集：`python -X utf8 -B -m unittest discover -s tests -v`。前端检查需要 Node；缺少 Node 时 unittest 会明确记录跳过。真实模型的自然语言映射、SQL 业务语义、隐藏任务泛化与成本对照属于后续实测，本阶段没有给出这些结论。
