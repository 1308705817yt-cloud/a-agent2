## 场景与共同条件

采用一个新合成的出库账本：24 行、4 个仓库，包含正常出库、负数调整、空数值和待处理记录。冻结十二题：十道计算题、两道非法输入题，覆盖自然语言分析、筛选、排序、参数优先级、空结果、count 计完整行及 column=null。人工答案先由独立 Decimal 计算器核对。

直接方案每题一次新的结构化 Codex 请求，提供完整原始数据、共同需求、默认规则和当前输入。完整流程全新构建 Agent，经过需求理解、工具与工作流设计、测试生成、源码生成、开发检查、保留验收及导出，随后对指纹绑定的冻结版本运行独立题。两者都使用相同数值、元数据和响应契约评分；执行自定义工具不是直接方案得分的条件。合法计算与非法输入分别统计。

两组均使用 Codex CLI 0.146.1、`cli_default` 请求配置并隔离用户配置。CLI 未暴露真实后端模型身份，`resolved_model=null`，因此不声称已确认具体模型完全相同。单请求与每题累计上限均为 600 秒，初始构建上限 3600 秒、最多三次源码修复，无 token 上限。两组同时启动，各组问题顺序执行，内部开发/验收使用项目默认并发。

独立答案、参考查询和未来问题没有进入构建、修复或当前题的模型上下文。独立评分不会触发源码修复。接续重用原产物，不重建、不改源码，不提供评分反馈。两个旧失败调用没有已提交工具观察，接续采用新的逐题执行额度，保留旧调用、耗时与失败。原报告和 ZIP 的不可变校验都通过。

协议、冻结输入及脚本见 [实验协议](../experiments/csv_comparison_protocol.md)、[冻结测试集](../experiments/csv_comparison_v1.json)、[首次执行脚本](../experiments/run_csv_comparison.py)、[接续脚本](../experiments/resume_csv_comparison.py)。

## 暴露的问题与验证范围

1. **重复决策开销。** 小规模账本的计算正确性双方持平；完整流程的合法题固定多出数据质量工具与查询的决策轮次。后续可评估按资源指纹复用确定性质量检查，以及一次决策安排多个独立工具。需要另设冻结评测验证收益，本轮未修改运行机制。
2. **设计契约仍会矛盾。** 生成指令明确将 `limit=0` 视为合法，开发用例 `dev-mean-positive-limit` 的 criterion 也要求空结果；宿主与共同判分器要求返回 INVALID_INPUT，实际因此通过。该用例验证了拒绝边界，没有验证其描述中的均值计算。39/39 内部检查通过并未消除这处设计矛盾，建议在冻结前检查设计声明与宿主契约的一致性。
3. **服务错误与源码错误需分开。** 超时审计为 `task_deadline`，依据 `caller_deadline/runtime`；下一题为 `rate_limit`，依据 CLI 的 `turn.failed → error.message → quota_or_rate_message`。无法由这些记录确认超时的底层原因，不能把两者当作确定源码缺陷。未改源码后接续成功，也不能归因于源码修复。

原始协议检查 8/8、接续证据回归 4/4 通过，覆盖冻结答案、上下文隔离、共同评分、未知调用量、旧失败保留和新审计隔离。导出包的文件/契约完整性及本地工具验证通过：开发工具用例 7/7、验收工具用例 6/6；这十三个本地测试没有新增模型调用，不替代真实行为评测。

这是一个小合成场景与一次有效构建的描述性对照。网络波动、并行调度和模型服务状态影响耗时，本次观察不构成稳定时延或生产泛化保证。直接方案代表一次结构化模型回答，不代表允许 Python、文件工具及其他内置能力时的最佳 Codex CLI 表现。评分检查完整计算数据及响应契约，没有验证自然语言回答中每一句解释。
