# AgentForge

## 当前结构与业务契约调整（已完成第 1 阶段架构验证）

生成器允许零自定义工具，并优先复用内置能力。常规查询可直接执行或一次规划；可选工具不再阻止快速路径，必需步骤与复杂任务仍保留决策循环。资源级 `csv.profile` 按数据和实现指纹复用。旧冻结产物仍使用原运行时。

新增可执行数据契约：字段映射、类型/空值/精度、日期时区、主键和业务指标；保留原始行和规范化记录。`csv.metrics` 执行精确十进制指标、去重、比值与多维分组，`csv.sql` 提供只读关系查询；可信数据库可显式配置 `sqlite_query`。无扩展代码的 CSV Agent 复用宿主输出模板，符合契约的新 CSV 可通过 `--bindings-json` 绑定到单独的执行快照。新生成的验收场景明确区分计算和拒绝，旧验收不会被当作新能力的证明。

新增模块、15 个三路径路由样例、零自定义工具的生成/验收/独立导出已经过本地自动化验证，并复跑完整旧测试。验证采用模拟模型响应和真实宿主执行，未调用真实模型，不能据此声称自然语言准确率或性能已提升。结果与复现命令见 [第 1 阶段验证报告](docs/phase1-architecture-validation.md)。接口、配置示例与证据边界见 [业务契约与复用说明](docs/agent-quality-contracts.md)，查询路由见 [结构调整说明](docs/structural-query-routing.md)。

**用 Codex 构建 Agent 的本地工程平台（v0.12）。** 输入任务需求与资源，生成 Agent 指令、工具契约、必要的自定义工具源码和验收场景；从实际失败中定位问题、修改代码、重新测试，最后导出独立运行包。子 Agent 按任务采用确定性查询、一次模型规划或 Codex 决策循环。

当前覆盖 **文档问答** 与 **CSV 数据分析**。生产流程只使用真实 Codex CLI，不包含本地模拟模型或离线回退。

## v0.12：参数来源、行数契约与评分边界

子 Agent 的 `input_contract` 区分用户参数、人工补充与默认值。自然语言目标可以覆盖未显式指定的默认筛选、排序和条数；显式 `[]`、`false`、`null` 仍是用户选择。人工接续后重新合并原始参数，避免把默认值或派生值变成用户约束。主查询由宿主核对显式参数，自然语言参数也在调用模型前校验。

`count` 始终统计筛选后的完整行，包含数值列为空的记录，返回 `column=null`。运行时、工作流与独立 Decimal 计算器保持一致。兼容传入有效列名，但无计数语义；非法列名或类型仍被拒绝。历史评测读取时记录旧 count 元数据的转换，原始冻结文件和数值答案不变。

开发、验收与独立文档评分共用事实和引用检查：否定事实或只提旧规不能替代现行回答；无关否定词不能豁免同句中的错误结论。事实短句可省略末尾句号或分号，引用本身仍必须是原文连续片段。规则只覆盖已测的字面和子句边界，不是通用语义裁判。

确定性修改前/后对照与复跑命令见 [v0.12 验证报告](docs/verification-v0.12.md) 和 [原始结果](docs/verification-v0.12.json)。上述修复验证没有真实模型调用，不能据此宣称交付率提升。新构建使用新运行时，已生成产物继续使用各自冻结版本。

## v0.11：独立计算覆盖与有执行条件的恢复

测试生成、冻结校验、实际评测入口与独立导出验证共用覆盖规则。每个工具的开发分区至少有两个不同的合法计算输入；验收分区至少有一个区别于开发输入的计算结果断言。两个分区分别保留宿主拒绝样例，以及设计 `error_cases` 中全部业务错误的合法输入和结果断言。宿主负例与业务错误不能抵消计算样例的最低数量；只有非法参数负例的工具验收不会通过。

逐用例恢复格式升级为 v2，每次评测和用例记录实际 `max_seconds`、模型配置、CLI 程序身份、单次请求时限及条件指纹。时限放宽时可继续已有任务，报告明确区分本次执行、历史复用和检查点接续，并保留各自原始条件；时限收紧（包含从不限改为有限）、模型配置或单次请求时限改变时，重新执行并停止复用旧观察。缺少条件的旧记录保留为历史，不能证明新条件下通过。使用 CLI 默认模型时，记录 requested_model=cli_default 和 resolved_model=null，不能把未暴露的后端模型身份当作已知。调用审计另记录实际被任务剩余时间截断后的请求时限。

评测报告记录各阶段调用数、操作人员方向、独立场景请求的人工回复，以及恢复复用的历史调用和已提交决策。`avoided_decision_reexecution` 是免于重复执行的已提交决策数的下界估计，不等于做过完整反事实重跑；没有自然中断时，恢复使用量如实为零。历史失败任务重建归入 historical_regression，新合成任务归入 novel，分别报告首次交付和修复，避免混合成泛化成功率。

本轮离线验证 **210/210** 通过。真实评测结论见 [v0.11 验证报告](docs/verification-v0.11.md)，完整证据见 [verification-v0.11.json](docs/verification-v0.11.json)。固定的新集 `unseen_v6` 包含两个 CSV 任务和一个文档任务，18 个答案在构建前人工指定，12 个数值问题另用 Decimal 独立核对，答案不会进入生成或修复。

历史失败任务重新构建后，快递重量独立通过 **4/6**、厨房账本 **5/6**，完整首次交付仍为 **0/2**；耗时 30.33 分钟、191 次模型调用、1 次设计修复。新任务原始尝试因两次额度错误及一次进程中断而未观察到交付；按原任务 ID 恢复后，文档任务经 2 次自动修复独立通过 **6/6** 并导出，两项新 CSV 均在设计调用触发 600 秒超时，源码尚未生成，12 个独立用例未执行。恢复批次耗时 37.23 分钟、新增调用 131 次，不包含会话中断间隔；恢复成功不能计为首次交付成功。

当前真实失败还包括默认参数被当成用户显式参数、count 结果列信息未归一，以及长设计调用超时。文档修复曾修改工具片段标点而违反计算契约，最终改为保持工具契约、从已读原文取得完整引用。验收覆盖和恢复记录机制已有验证，但这些有限样本尚不能证明交付率提升。

## v0.10：宿主负例、调用分类与逐用例恢复

工具测试有两类互斥断言：合法参数使用 `expected_json` 验证计算或工具业务错误；参数类型、必需字段、未知字段及宿主大小约束的负例使用 `expected_error={"code":"INVALID_ARGUMENTS","origin":"decision","layer":"host"}`，`expected_json=null`。宿主负例调用真实参数校验入口，不执行工具源码。新设计声明 `error_cases`，在生成源码前检查错误应由 host 还是 tool_result 处理；两个测试分区保留设计中的宿主负例，负例不能替代两组不同的合法开发输入。矛盾反馈保留用例 ID、字段路径、期望类型、实际类型和拒绝层；拒绝的测试草稿及反馈继续保存。

Codex 调用失败优先解析 `turn.failed`、`error` 和错误 item 的明确错误字段；业务输出不参与分类。无法可靠识别时保留 unknown，403 归为权限不足，服务请求超时与本地进程超时保留各自依据。审计增加脱敏的 `error_category`、`exit_code` 和 `classification_basis`，不保存原始错误文本。混合 MODEL_ERROR/MODEL_TIMEOUT 不再汇总为单一 MODEL_TIMEOUT。历史厨房任务的旧记录无法证明认证、额度、模型不可用等提示各自的真实原因，原因保持未确认，也不据此自动延长超时。

开发及保留验收逐用例提交 `*_case_progress.json`，保存已完成结果和中断用例的决策/观察检查点。`retry` 和崩溃后的 `recover` 复用已完成用例，只执行中断或尚未提交的用例；已经提交的只读工具观察不重做。普通业务或源码验收失败仍计为失败，不能靠重试绕过。恢复记录绑定当前产物（含运行时）、资源、需求、测试集、分区及逐用例输入/断言指纹；版本或测试变化时重新验证，完整性不符拒绝复用。报告分别记录累计模型调用和本次新增调用，以及 reused/executed/resumed 用例 ID；页面展示中断报告和恢复状态。

工程验证与安装包证据见 [verification-v0.10.json](docs/verification-v0.10.json)。本轮回归使用确定性故障注入，不调用真实模型；v0.9 的陌生任务首次交付率及原始报告保持原值，修复效果需后续新任务测量。旧任务使用原冻结运行时，不自动获得新版本的逐用例记录。

## v0.9：大结果边界与可信依赖归因

解释器每次运行先初始化行号、步数和环境，再检查输入大小。120001 字符结果及超过输出钩子预算的合法工具结果均返回结构化 CODE_LIMIT，带位置和恢复方向；输入尚未执行源码时标记 runtime，执行源码扩张数据超限仍标记 source。预算超限显式暴露，供工具结果设计和运行预算调整使用。

可信 HTTP 返回值违约、无效 JSON 和内容类型错误标记 external，认证及 SQLite 绑定错误标记 configuration；瞬时网络错误、429 和 5xx 可以在现有决策预算内重试。审计和最终结果保留一致的错误来源。构建验收遇到失败的可信依赖时保留报告并停留在当前测试阶段，不启动源码修复；服务恢复后重试同一版本，冻结绑定配置变更则需新构建。生成自定义工具的契约缺陷仍标记 source。

新增 14 项边界回归，覆盖精确 JSON 大小阈值、重复运行、完整子 Agent 路径、HTTP 状态分类及构建恢复；全量 176 项通过。安装后的 v0.9 wheel 同样复现并返回 CODE_LIMIT。证据见 [verification-v0.9.json](docs/verification-v0.9.json)。

本轮 unseen-v5 使用四个全新合成任务、24 个预先固定的独立用例，零产物复用、零人工重试：首次交付 **2/4（50%）**，首次候选 **0/4**，自动修复 2 次，整批墙钟 **1918.44 秒（约 32 分钟）**，累计 **367 次**模型请求（含 5 次失败请求）。园区施工和档案查阅均修复一次后通过内部验收及各自 6 个独立用例。物流在测试生成阶段连续产生与参数契约冲突的负例而失败；食材 v1 开发 16/16，通过开发后在保留验收遇到 Codex 调用失败，停留在 acceptance，未触发源码修复。已执行的 12 个独立用例全部通过；其余 12 个未执行，按未交付计失败，不能解释成 12 个数值或事实答案错误。原始报告保存在 evaluations/2168b134203b/report.json。

本轮仅四个公开合成任务，不能推断任意陌生任务的成功率。构建上限为每任务 1800 秒，开发和保留验收每次运行上限 600 秒、单次模型调用上限 600 秒；独立用例使用各冻结产物的 execution_policy，整批未设置全局时限。v0.9 当时最明确的剩余缺口是测试负例与工具调用契约的衔接，以及模型调用中断后的交付恢复；v0.10 针对这些边界补了工程回归，尚未重测陌生任务交付率。

## v0.8：输出预检、错误归属与解释器匹配

初次生成、代码修复、设计修复和运行时升级在创建新版本前，都会静态检查工具源码并执行输出钩子契约预检。检查成功、拒答、错误响应以及空值、嵌套对象、数组和数值等主机载荷；使用真实的有效参数形状，文档自然语言目标不会凭空补 question/goal 字段。`logic.py` 只能修改 answer，必须完整保留 data/sources/abstained/error；result_ref 只存在于 Codex 决策，主机已将引用解析为 data，不提供 final_response 标志。每个版本和导出包附 source_preflight.json，本地检查不新增模型调用，也不读取保留验收答案。

错误记录含 origin、retryable、recovery 和源码位置。生成源码异常、自定义工具输出 schema 违约和输出钩子篡改以 source 标记，运行时立即停止并进入构建诊断与修复；无效参数、未完成必需工具、错误结果引用和来源选择以 decision 标记，继续提供反馈，由子 Agent 调整。源码预检失败最多进行三次生成纠正，拒绝的初次源码及修复源码均留存，失败源码不会建立新版本。诊断与修复同时收到真实响应契约和解释器能力，避免建议不存在的框架接口。

新工具设计必须声明 execution_plan，说明算法和所需 helpers/AST 语法。设计器读取与实际解释器共用的能力清单、helper 参数数量、资源访问范围和执行预算；未知 helper 或不支持的 AST 在设计阶段被拒。新设计还需提供可变参数，以构造两组不同的合法开发输入；无参数且绑定固定资源的设计会在测试冻结前被要求调整。复杂语义交给运行时 Codex，工具使用可执行的有界数据算法。代码阶段继续校验实际 AST 和调用签名，旧产物仍使用各自冻结的运行时。声明通过不能证明算法正确或所有规模下均满足预算，业务测试和运行时检查仍必需。

工程验证：162 项回归检查通过；重放 v0.7 实验室实际输出源码，在新增模型调用 **0 次** 时拦截缺少 data/error、多出 result_ref，并给出 logic.py:39。验证报告见 docs/verification-v0.8.json。真实 Codex 新任务结果在报告中单独记录，不改写 v0.7 的首次交付率。

## v0.7：超时、审计和任务分页

单次模型请求超时为 `MODEL_TIMEOUT`，子 Agent 与构建总时限为 `TASK_TIMEOUT`（分别标明 runtime/build），可信工具超时为 `TOOL_TIMEOUT`。前两类保留当前阶段和已提交观察；最后一条已保存的决策即使达到累计调用上限，仍可恢复执行，不新增模型请求；测试阶段的超时不会被当作代码缺陷送进修复。测试中子 Agent 时间不够时，可用 `retry <任务ID> --run-max-seconds 1200` 调整上限；构建时间不够时使用 `--max-seconds`。

v0.7 的构建与子 Agent 每次 Codex 请求在 `runs/<任务ID>/calls/<call_id>.json` 独立记录开始、完成/失败、调用阶段、用例 ID、耗时和已返回的 usage；进程中断前开始的请求保留为 inflight。记录不保存提示词、文档正文、参数原值或认证信息。并行调用的模型元数据和可信工具审计按线程隔离，可信工具附独立 call_id、参数哈希及结果哈希。调用量包含生成、格式重试、测试、诊断、修复和独立评测，不从阶段事件推算，不设 token/费用预算。旧版本未记录的请求不能补算，控制台会标注历史运行时缺少完整调用量。

任务列表采用固定创建时间与 ID 的游标分页（每页 1–200 个），更新任务不会把它移动到另一页。`GET /api/jobs?limit=50&cursor=<next_cursor>` 返回 jobs、next_cursor、total 和全库 status_counts。控制台可翻页并在当前浏览器会话恢复页码；服务启动与 CLI 完整扫描全部页，超过 200 个任务时也会恢复较早的排队任务。旧 SQLite 索引自动迁移，旧产物仍使用冻结运行时。

新评测集 `agentforge/benchmarks/unseen_v3.json` 含 4 项新合成任务、24 个手写独立问题；答案先于构建冻结，不反馈给生成与修复。评测区分首次自动交付（允许预设自动修复、禁止人工重试/复用）和首版成功（还要求 v1、零修复），全部选定任务进入分母；复用产物的评测不计算首次交付率。报告同时记录修复次数、活跃耗时、真实墙钟耗时、构建及全流程审计调用量。

```powershell
python -X utf8 -m agentforge benchmark run --suite agentforge/benchmarks/unseen_v3.json --task-workers 2 --max-repairs 3 --max-seconds 1800 --run-max-seconds 600 --timeout 600
```

每个并行构建持有独立 planner、时限和租约；单个任务异常会写入报告，其余任务继续。当前真实结果会保存在 evaluations/<评测ID>/report.json，不能用以往修复后通过的产物冒充首次交付成功。

| 实验室预约 | 3 次修复后开发检查 4/13，停止 | 3 | 22.7 分钟 | 169 |
| 订阅退款 | 单次模型请求超时 | 0 | 10.5 分钟 | 2 |
| 供应商发货 | 开发 24/24，保留验收 4/5，拒绝交付 | 0 | 9.8 分钟 | 46 |
| 电表净用电 | 单次模型请求超时 | 0 | 10.3 分钟 | 2 |

本轮没有合格产物，因此 24 个独立问题未运行，按交付协议计失败；这些数字不能解读为“24 道实际回答全部答错”。219 个调用 ID 全部唯一，217 次后端请求完成、2 次请求超时，0 条未提交记录；任务与审计文件绑定无错误，观测到最高 6 个同时进行的请求。

静态执行核实实验室输出钩子丢失主机要求的 data/error，并额外输出 result_ref，导致 OUTPUT_CONTRACT 后重复 finish、最终耗尽决策步数。模型最后的诊断还建议了框架不存在的 final_response 标志，未被采纳。这批任务说明源码输出契约约束、修复诊断可靠性和工具样例质量仍需改善；工程检查通过不能证明新任务可交付。完整验证及安装包指纹见 `docs/verification-v0.7.json`。

## 核心能力

| 能力 | 实现 |
| --- | --- |
| 需求理解 | Codex 提取任务类型、默认分析参数和验收条件；超出能力的需求会明确停止 |
| 工具选择 | 选择内置工具并按需求定义 1–3 个自定义工具，冻结参数及输出契约 |
| 子 Agent 决策循环 | Codex 计划 → 选择工具 → 主机执行 → 观察结果/错误 → 调整计划 → 校验返回，支持请求补充输入 |
| 自定义工具代码 | 生成 `custom_tools/*.py`，可计算数据质量、业务指标、文档结构等；可读取授权资源和已有观察 |
| 代码与设计修复 | 根据真实失败选择修改实现或重设工具接口；连续修复没有进展时自动升级为设计修复 |
| 执行性能 | 复用已完成的内置计算，显式提示完成条件，有进展时自动延长决策步数；不设 token 配额 |
| 总耗时控制 | 构建与运行分别设置累计上限；超时保留阶段与检查点，调整上限后继续，0 表示不限 |
| 按需求生成测试 | 源码生成前冻结需求场景、工具样例及自然语言目标；开发与保留验收分开 |
| 数值验收 | CSV 预期结果由独立 Decimal 计算器产生，避免模型自行提供数值答案 |
| 独立陌生任务评测 | 固定手写任务和标准答案，与生成及自动修复隔离；保存逐例结果 |
| 运行恢复 | 保存决策、观察、人工回复与调用数；异常后显式续跑 |
| 可信工具接入 | 运维配置的只读 SQLite 与固定 HTTP JSON GET，契约、限额和审计记录 |
| 人工方向 | 开发失败后可暂停并输入修改方向，或自动完成有限次数修复 |
| 交付 | 通过两层检查后导出目录和 ZIP，附版本、指纹、测试报告和文件校验清单 |

每个版本保留指令、工具源码、测试结果、诊断与差异。资源、需求和业务开发/保留验收场景冻结。代码修复保持工具接口；设计修复可改变接口，并在生成新源码前独立生成接口测试，保留原业务场景及旧版本证据。未变的接口继续使用原工具测试。保留验收失败会阻止导出，本轮不会把这些用例反馈给修复模型。

新工具的契约需明确每个输出字段的计算、排列、去重和空值规则；生成源码前检查每个工具至少有两个不同输入的开发样例，并要求模型覆盖正常与边界计算。这项检查保证样例输入有差异，不能自动证明所有业务分支都已覆盖。文档工具优先整理可核验的原文证据，政策含义由运行时 Codex 判断，避免在用户未要求时额外生成整套领域规则解析器。生成测试 ID 的格式修正发生在冻结前，不改变问题、事实或判分标准。

源码生成和代码修复阶段先校验工具 ID、实际语法、调用签名及输出钩子的执行契约，最多直接纠正三次契约错误，再建立可测试版本。被拒源码与错误位置保留在构建或设计目录中；这些生成尝试也计入构建总耗时。

## 启动

需要 Python 3.11+、已安装并登录的 Codex CLI。运行时只依赖 Python 标准库。

```powershell
codex login
python -X utf8 -m agentforge doctor --probe
python -X utf8 -m agentforge serve
```

打开 **http://127.0.0.1:8787**，填写需求、上传资源并开始构建。控制台展示真实任务状态、工具工作流、源码、测试证据和版本差异，并提供试运行与 ZIP 下载。

也可以安装命令行入口：

```powershell
python -m pip install -e .
agentforge serve
```

工作区默认为当前目录；全局参数 `--workspace <目录>` 应放在子命令前。端口可通过 `serve --port 8788` 调整。

构建时需求、文档内容预览、CSV 表头和前 12 行、开发失败证据会发送到当前 Codex 服务。运行时模型还会收到工具结果和读取的文档片段。完整资源快照保存在本机并随独立包导出。示例文件为合成数据；系统不会自动使用示例资源。

## 命令行工作流

### 文档问答

```powershell
python -X utf8 -m agentforge create --request "基于上传的虚构测试制度回答问题，摘取原文并引用来源，没有证据时拒答" --documents examples/synthetic_documents.json --review
```

支持 TXT、Markdown 和文档 JSON。JSON 格式：

```json
[
  {"id": "policy-1", "title": "政策", "content": "可引用的原文。"}
]
```

也接受 `{"documents": [...]}`。子 Agent 可以先搜索或分页读取原文，再由 Codex 理解问题、调用生成的文档工具并组织回答。引用必须来自实际读取的片段且可在原文核对。支持语义改写；PDF/OCR 和向量检索尚未实现。来源校验不能保证所有问题的语义回答正确。

### CSV 分析

```powershell
python -X utf8 -m agentforge create --request "生成数据质量工具检查 amount 空值及总额，再按 region 汇总 amount，按金额降序；支持自然语言目标和参数覆盖" --csv examples/sales.csv
```

基础查询支持单个绑定数据集的筛选、分组、聚合、排序与数量限制；自定义工具可以实现其他纯数据计算。运行可以使用自然语言目标或 JSON 参数：

```powershell
python -X utf8 -m agentforge run <任务ID> --input-json '{"operation":"sum","column":"amount","group_by":"region","sort_by":"value","descending":true,"limit":2}'
python -X utf8 -m agentforge run <任务ID> "检查金额缺失情况，再比较各地区总额"
```

| 参数 | 可用值 |
| --- | --- |
| operation | sum / mean / count / min / max |
| column | 数值列；count 的结果固定为 null（兼容有效输入列名） |
| group_by | 列名或 null，null 表示不分组 |
| filters | `[{"column":"region","operator":"eq","value":"East"}]` |
| 筛选运算符 | eq / ne / gt / gte / lt / lte / contains |
| sort_by | group / value / count |
| descending | true / false |
| limit | null 或 1 至 1000 的整数 |

空数值单元格不参与基础数值聚合；count 计筛选后的行数。文本比较区分大小写。每组查询结果包含 group、value、count。查询使用浮点聚合，独立验收使用 Decimal 后以容差核对。最终 data 引用主机实际执行的观察，输出代码不能篡改数值。自定义工具样例由模型在看到源码前单独生成，能发现代码偏差，但不是所有业务计算的正确性证明。

子 Agent 的 max_steps 是每段决策目标（3–16 步）。新构建默认启用自适应扩展：出现新的成功工具结果时可增加决策步数；重复相同失败不会无限延长，累计仍最多 3 倍。重复相同工具参数超过两次会收到错误；已完成的内置查询和读取会复用观察，自定义及实时可信工具保持正常执行。决策预算耗尽、模型调用失败和工具错误都有明确记录。复杂目标可以用 `{"goal":"目标","parameters":{}}` 输入；可通过配置接入可信只读工具，新增任务类型仍需扩展实现。

### 设计修复与时间控制

诊断为接口/工具划分问题时，工厂进入 `redesign → redesign_tests → redesign_code`；连续代码修复在同一测试集、同一批实际检查中没有进展时，也会重新设计。工具失败后跳过的业务测试，不会与此前完整测试的通过率直接比较；接口变更后的新测试也不与旧接口分数比较。原业务目标、资源和所有业务测试保持不变，保留验收失败仍阻止交付。本轮不会把独立评测答案或保留验收失败传给修复。

默认构建累计上限为 60 分钟，子 Agent 默认为 15 分钟；包含模型及工具时间，人工等待不计入。上限可调或设为 0；不设置 token/费用配额。单次 Codex 超时仍由 `--timeout` 控制。

```powershell
python -m agentforge create --request "你的需求" --csv data.csv --max-seconds 7200 --run-max-seconds 1800
python -m agentforge retry <任务ID> --max-seconds 0
python -m agentforge retry <停止任务ID> --max-repairs 5 --repair-scope design --direction "简化工具接口，保留业务验收"
python -m agentforge continue-execution <任务ID> <执行ID> --max-seconds 1800
python -m agentforge upgrade-runtime <未交付任务ID> --timeout 600
```

达到修复轮次上限后可在原任务上增加轮次（最多 20）并继续，也可指定 code/design 范围；仍需通过原业务验收。`--fixed-steps` 可关闭自动决策扩展。控制台创建表单和超时接续操作也提供时间设置。

受信运行器修复后，未交付任务可用 `upgrade-runtime` 生成新的运行时版本并重新执行全部验收，保留原版本和冻结测试。自定义工具可用 `is_object`、`is_array`、`is_string` 校验嵌套 JSON 数据，再取字段；辅助函数的类型错误会记录具体工具行号，不会直接击穿构建进程。

### 查看、恢复与运行

```powershell
python -m agentforge list
python -m agentforge show <任务ID> --json
python -m agentforge diff <任务ID> --version 2
python -m agentforge resume <任务ID> --direction "保留来源原文，调整输出格式"
python -m agentforge retry <任务ID>
python -m agentforge recover <任务ID>
python -m agentforge upgrade-runtime <未完成任务ID>
python -X utf8 -m agentforge run <任务ID> "每年有多少天年假？"
python -m agentforge tools
```

`resume` 用于等待人工方向的任务；方向可省略。`retry` 用于模型/系统调用失败，从保存的阶段和逐用例进度恢复；已完成验收用例复用，中断用例继续检查点，修复预算不重置。`recover` 处理排队或崩溃后遗留运行任务。`--max-repairs` 为 0 至 20，默认 3。

运行时升级后，未完成任务可用 `upgrade-runtime` 生成新版本、保留原契约并重跑全部验收。已完成任务使用其导出包中校验过的原运行时，在控制台也能继续运行。新版本还保存运行时源码快照，使未交付候选的已有执行也能沿用原运行时接续；旧任务缺少快照时需要 upgrade-runtime。正常文档回答必须执行必需工具；核对资源目录后对域外问题明确拒答的路径可免执行业务工具。

## 陌生任务评测与运行接续

内置 `unseen-v1.1` 包含 2 个陌生业务任务、12 条固定场景。制度任务覆盖现行/废止规则、跨文档回答、拒答和不可信留言；账本任务覆盖完整行、负数退款、全空列、空筛选和人工补充。资料是显式虚构数据。标准答案和判分规则不进入工厂；仅构建完成后对冻结版本运行。评测失败不会触发使用标准答案的自动修复。

```powershell
python -m agentforge benchmark list
python -X utf8 -m agentforge benchmark run --timeout 360
python -X utf8 -m agentforge benchmark run --task returns_ledger --run-id <相同任务的构建ID>
python -X utf8 -m agentforge continue-execution <任务ID> <执行ID> --reply "以净额为指标"
```

真实评测会构建 Agent 并消耗 Codex 额度。报告保存在 `evaluations/<评测ID>/report.json`，工作台测试页也显示结果。也可用 `--evaluate-generated --run-id <ID> --task <匹配任务>` 单独诊断冻结的未交付候选；该结果不会改变交付状态。它是公开的固定回归集，适合度量当前两类能力；若人工根据失败修改产品，后续需要新增未见用例，不能继续把同一套场景当成未污染的盲测。

子 Agent 的 `waiting_input` 状态接受文字回复，CSV 可附 parameters；工作台运行页可直接提交。模型故障和进程中断可以从最后保存的决策状态显式恢复，已完成工具观察保留。尚未提交的只读调用可能重读；未提交模型请求计入预算，新请求仍可能消耗额度。每段以 max_steps 为目标，有进展可自动延长；累计最多 3 倍，人工回复最多 5 次。历史 v0.4 导出运行时保持原行为，新增接续能力需要新构建。

可信工具由根目录 `trusted_tools.json` 配置，在工具页可查看。详见 [可信工具接入](docs/tool-integrations.md)。SQLite 数据库和服务密钥不自动进入导出包。

## Codex 配置

复用现有登录认证，通过 `codex exec` 的结构化输出调用模型。默认不固定模型名称，使用账号可用的 CLI 默认模型；可用 `--model` 或 `AGENTFORGE_CODEX_MODEL` 指定。单次请求默认超时 180 秒，可用 `--timeout` 调整到 600 秒以内。

项目使用 `--ignore-user-config` 隔离可能影响结构化构建的全局运行配置，同时保留登录；使用只读沙箱和关闭交互审批的调用方式。不会修改全局 Codex 配置。原生二进制可通过 `AGENTFORGE_CODEX_BIN` 指定。
